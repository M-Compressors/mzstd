# lzbench run, 2026-11-09

mzstd 0.2.12 and the previous release, 0.2.11, against zstd 1.5.7, measured
with the lzbench in-memory benchmark on the Silesia corpus. The README's
lzbench table is taken from the 0.2.12 rounds.

## Environment

- lzbench master at
  [`a6fa8aa`](https://github.com/inikep/lzbench/tree/a6fa8aa758932a02841c0cc68c07e5abf8870951)
  (2026-11-07), reporting itself as lzbench 2.4.1. It vendors zstd 1.5.7
  and mzstd 0.2.11. For the 0.2.12 build, its `lz+entropy/mzstd` directory
  was replaced by this release's sources; lzbench still labels the codec
  "mzstd 0.2.11", the version its codec table names, so the 0.2.12 output
  below is relabelled.
- gcc 15.2.0, rustc 1.99.1. Built with
  `make BUILD_ONLY='ZSTD MZSTD' MOREFLAGS="-march=native"`; the Rust codecs
  use lzbench's default `RUST_TARGET_CPU=native`, so both sides target the
  same CPU.
- AMD Ryzen 9 7950X VDS (2 vCPU, KVM), Linux 7.0, default CPU governor and
  boost. The host is shared with other tenants, who loaded it throughout
  the day: a fixed C decode varied by 8-43% between its 10th and 90th
  percentile wall times. The benchmark is pinned to one vCPU with
  `taskset -c 1`.
- Input: `silesia.tar`, 211,957,760 bytes, the twelve Silesia files in a
  ustar archive, compressed as one stream.

## Command

```sh
taskset -c 1 ./lzbench -t8,8 -o1 \
  -ezstd_fast,-5/mzstd_fast,-5/zstd_fast,-3/mzstd_fast,-3/zstd_fast,-1/mzstd_fast,-1/zstd,1/mzstd,1/zstd,2/mzstd,2/zstd,3/mzstd,3/zstd,5/mzstd,5/zstd,8/mzstd,8/zstd,11/mzstd,11/zstd,15/mzstd,15/zstd,18/mzstd,18/zstd,22/mzstd,22 \
  silesia.tar
```

`-t8,8` repeats each compression and decompression for at least eight seconds
and reports the fastest iteration. Codecs are interleaved level by level so
that drift on the shared host affects both sides of a pair alike. Because
the host was loaded, the command ran in three rounds, each the 0.2.12
build followed by the 0.2.11 build (14:45 to 15:08 UTC, then 17:27 to 18:13
UTC). The tables below take, for every codec and level, the fastest result
of the three rounds, extending lzbench's own fastest-iteration rule; the
raw output of every round is at the end.

## Speed relative to zstd

Each value is mzstd's speed divided by zstd's, both the fastest of the
three rounds; the rounds columns give the ratio within each round. The two
releases are compared through the zstd beside them rather than through
absolute speeds. Compressed sizes are byte-for-byte equal at every level in
every round.

Decompression ratios reproduce within about 2% between rounds, except at
level 22 (0.921 to 0.998), and so does compression at the `--fast` levels
and level 1. Compression at level 2 and above moves by 3% to 21% between
rounds (level 8: 0.848 to 1.030) on this host, so differences of a few
percent there are within noise. Against 0.2.11, decompression is
faster relative to zstd at levels 1 to 22 (level 1: 0.883 to 0.933, level 2:
0.906 to 0.933) and level 3 compresses at about zstd's speed (1.011) instead of 0.973 of
it, from the branchy candidate tests of `dfast`.
