# lzbench run, 2026-11-08

mzstd 0.2.11 against zstd 1.5.7, measured with the lzbench in-memory benchmark on the Silesia corpus.
The README's lzbench table is taken from this run.

## Environment

- lzbench master at
  [`a6fa8aa`](https://github.com/inikep/lzbench/tree/a6fa8aa758932a02841c0cc68c07e5abf8870951)
  (2026-11-07), reporting itself as lzbench 2.4.1. It vendors zstd 1.5.7 and mzstd 0.2.11.
- gcc 15.2.0, rustc 1.99.1. Built with
  `make BUILD_ONLY='ZSTD BROTLI MZSTD MBROTLI' MOREFLAGS="-march=native"`;
  the Rust codecs use lzbench's default `RUST_TARGET_CPU=native`, so both
  sides target the same CPU.
- AMD Ryzen 9 7950X VDS (2 vCPU, KVM), Linux 7.0, default CPU governor and
  boost. The benchmark is pinned to one vCPU with `taskset -c 1`.
- Input: `silesia.tar`, 211,957,760 bytes, the twelve Silesia files in a
  ustar archive, compressed as one stream.

## Command

```sh
taskset -c 1 ./lzbench -t8,8 -o1 \
  -ezstd_fast,-5/mzstd_fast,-5/zstd_fast,-3/mzstd_fast,-3/zstd_fast,-1/mzstd_fast,-1/zstd,1/mzstd,1/zstd,2/mzstd,2/zstd,3/mzstd,3/zstd,5/mzstd,5/zstd,8/mzstd,8/zstd,11/mzstd,11/zstd,15/mzstd,15/zstd,18/mzstd,18/zstd,22/mzstd,22 \
  silesia.tar
```

`-t8,8` repeats each compression and decompression for at least eight seconds
and reports the fastest iteration. Codecs are interleaved level by level so
that drift on the shared host affects both sides of a pair alike.

## Repeatability

A second run of levels 1 and 3 right after the sweep measured:

| Compressor name | Compression | Decompress. |
| --------------- | ----------: | ----------: |
| zstd 1.5.7 -1   |    654 MB/s |   2119 MB/s |
| mzstd 0.2.11 -1 |    601 MB/s |   1879 MB/s |
| zstd 1.5.7 -3   |    371 MB/s |   1873 MB/s |
| mzstd 0.2.11 -3 |    354 MB/s |   1728 MB/s |

Every speed moved by at most 2%, so the gaps in the sweep, 2.5–12%, are
larger than the run-to-run noise. Compressed sizes are byte-for-byte equal at
every level.
